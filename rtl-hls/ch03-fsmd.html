FSMD: 컨트롤러와 데이터패스

Mealy/Moore FSM에 데이터패스를 붙여 숫자를 계산하고, 큰 FSM이 작은 FSM을 부리는 구조를 봅니다.

3.1FSM만으로는 계산을 못 한다

지난 학기에 만든 Mealy/Moore 머신의 입력은 대개 1비트였습니다. “1이 세 번 들어오면 출력” 같은 일은 잘하지만, 두 수의 최대공약수를 구하는 일은 어떨까요? 8비트 숫자 두 개를 상태로 표현하려면 상태가 65,536개 필요합니다.

그래서 숫자는 데이터패스(레지스터, 연산기, MUX)에 맡기고, FSM은 “이번 사이클에 데이터패스가 무엇을 할지”만 정하게 합니다. FSM 쪽을 컨트롤러라고 부르고, 둘을 합친 구조를 FSMD(FSM with Datapath)라고 합니다.

  • 컨트롤러 → 데이터패스: 제어 신호. 어느 레지스터에 쓸지(load), MUX가 무엇을 고를지(select).
  • 데이터패스 → 컨트롤러: 상태 신호. 비교 결과처럼 다음 상태를 정하는 데 필요한 정보.

3.2예제: 유클리드 호제법

while (a != b) {
  if (a > b) a = a - b;
  else       b = b - a;
}
return a;   // 최대공약수

이 C 코드를 하드웨어로 옮기면, 변수 a와 b는 레지스터 A와 B가 되고, 뺄셈은 감산기, 비교는 비교기가 됩니다. 반복문의 흐름은 컨트롤러의 상태가 됩니다.

  • IDLE: start가 오면 입력 a_in, b_in을 A, B에 싣고 CALC로.
  • CALC: A==B이면 DONE으로. 아니면 A>B일 때 A ← A−B, 아닐 때 B ← B−A를 하고 CALC에 머뭄.
  • DONE: done=1. start가 다시 오면 새 계산 시작.

CALC 상태에서 ld_a, ld_b는 상태뿐 아니라 상태 신호 gt에도 의존합니다. 즉 이 컨트롤러의 출력 일부는 Mealy 출력입니다.

위 회로를 Verilog로 쓰면 이렇습니다. 데이터패스, 상태 레지스터, 다음 상태/출력 논리를 세 덩어리로 나누는 것이 일반적입니다.

// 1) 데이터패스: 레지스터 + 연산기 + MUX
always @(posedge clk) begin
  if (ld_a) A <= sel ? (A - B) : a_in;
  if (ld_b) B <= sel ? (B - A) : b_in;
end
assign eq = (A == B);
assign gt = (A > B);

// 2) 컨트롤러: 상태 레지스터
always @(posedge clk)
  if (rst) state <= IDLE;
  else     state <= next;

// 3) 컨트롤러: 다음 상태와 출력 (조합 논리)
always @(*) begin
  next = state; ld_a = 0; ld_b = 0; sel = 0; done = 0;  // 기본값 먼저!
  case (state)
    IDLE: if (start) begin ld_a = 1; ld_b = 1; next = CALC; end
    CALC: if (eq)      next = DONE;
          else if (gt) begin ld_a = 1; sel = 1; end
          else         begin ld_b = 1; sel = 1; end
    DONE: begin
            done = 1;
            if (start) begin ld_a = 1; ld_b = 1; next = CALC; end
          end
  endcase
end
기본값을 먼저 대입하는 이유 always @(*) 안에서 어떤 경로로 들어갔을 때 ld_a에 아무것도 대입하지 않으면, “이전 값을 유지하라”는 뜻이 되어 합성기가 래치를 만듭니다. 블록 첫 줄에 모든 출력의 기본값을 적어 두면 이 실수를 원천적으로 막을 수 있습니다.

3.3큰 FSM이 작은 FSM을 부리기: major/minor FSM

이번엔 세 수 x, y, z의 최대공약수를 구한다고 해 봅시다. gcd(gcd(x, y), z)이므로 위의 GCD 회로를 두 번 쓰면 됩니다. 모든 경우를 상태 하나짜리 FSM에 몰아넣는 대신, 일의 순서를 지휘하는 major FSM과 실제 계산을 하는 minor FSM(위의 GCD 회로)으로 나눕니다. 함수 호출과 비슷합니다.

둘은 start와 done 두 신호로 대화합니다. major는 start를 한 사이클 올려 일을 맡기고, minor가 done을 올릴 때까지 대기 상태에서 기다립니다.

이렇게 나누면 각 FSM이 단순해지고, minor FSM은 다른 곳에서 그대로 다시 쓸 수 있습니다. 대가는 start/done을 주고받느라 생기는 몇 사이클입니다. 6장에서 보겠지만, HLS 도구도 C 함수 하나를 이런 식으로 FSM과 데이터패스로 바꾸고, 함수 호출은 start/done 핸드셰이크로 바꿉니다.

3.4알고리즘에서 FSMD까지: 설계 절차

앞에서는 완성된 GCD 회로를 보았습니다. 새 문제를 혼자 풀 때는 아래 절차를 따르면 막히지 않습니다.

  1. 알고리즘 쓰기: C나 의사코드로 한 번 씁니다.
  2. 재료 정하기: 변수는 레지스터, 연산은 연산기, 조건은 비교기가 됩니다. 비트 폭도 이때 정합니다.
  3. ASMD 차트 그리기: 상태(사각형), 판단(마름모), 조건부 출력(둥근 상자)으로 사이클 단위 흐름을 그립니다. 사각형 하나가 한 사이클입니다.
  4. 데이터패스 그리기: 레지스터마다 어떤 값이 들어올 수 있는지 보고 MUX와 load 신호를 붙입니다.
  5. 컨트롤러 표 만들기: (현재 상태, 상태 신호) → (다음 상태, 제어 신호) 표를 만들면 그대로 case 문이 됩니다.

GCD의 ASMD 차트는 이렇습니다. 실험 3-1의 상태도와 Verilog를 이 그림과 한 줄씩 맞대어 보세요. 그림을 단순하게 하려고 DONE에서 start를 다시 보는 부분은 생략했습니다.

연습: 4비트 수 두 개를 곱하는 시프트-덧셈 곱셈기를 같은 절차로 설계해 보세요.

P = 0;  A = a;  B = b;  n = 4;
while (n != 0) {
  if (B & 1) P = P + A;
  A = A << 1;  B = B >> 1;  n = n - 1;
}
return P;
답 보기

레지스터는 P(8비트), A(8비트), B(4비트), n(3비트)입니다. 연산기는 덧셈기 하나, 시프터 둘, 감산기(또는 카운터) 하나, n==0 비교기 하나입니다.

현재 상태조건다음 상태제어 신호
IDLEstart=1RUNP←0, A←a, B←b, n←4
RUNn==0DONE없음
RUNn!=0, B[0]=1RUNP←P+A, A←A<<1, B←B>>1, n←n−1
RUNn!=0, B[0]=0RUNA←A<<1, B←B>>1, n←n−1
DONE-DONEdone=1

RUN 상태에서 P를 쓸지(ld_p)가 B[0]에 따라 달라지므로 이 출력도 Mealy입니다. GCD와 똑같은 모양이라는 점을 확인하세요.

감산기 하나로 줄이기: 자원 공유

GCD 데이터패스에는 A−B와 B−A 감산기가 두 개 있지만, 한 사이클에 둘 중 하나만 씁니다. 큰 쪽과 작은 쪽을 MUX로 먼저 고르면 감산기 하나로 충분합니다.

wire [7:0] big   = gt ? A : B;
wire [7:0] small = gt ? B : A;
wire [7:0] diff  = big - small;          // 감산기 하나를 두 경우가 나눠 씀
always @(posedge clk) begin
  if (ld_a) A <= sel ? diff : a_in;
  if (ld_b) B <= sel ? diff : b_in;
end

감산기는 하나 줄었지만 MUX 두 개가 생기고, 비교 → MUX → 뺄셈으로 경로가 길어집니다. 연산기를 줄이는 대신 MUX와 지연을 내주는 이 맞교환이 6장에서 HLS 도구가 하는 바인딩의 핵심입니다. 감산기처럼 작은 연산기라면 공유하지 않는 편이 나을 때도 많고, 곱셈기처럼 큰 연산기일수록 공유할 가치가 큽니다.

3.5상태 번호 붙이기와 출력 글리치

상태를 플립플롭에 어떻게 담을지도 설계자가 정합니다. 상태가 N개일 때 방법은 크게 셋입니다.

  • binary: 0, 1, 2, …를 그대로 씁니다. 플립플롭은 log2N개로 가장 적지만, 다음 상태 논리가 모든 비트를 봐야 해서 복잡해지기 쉽습니다.
  • one-hot: 상태마다 플립플롭 하나, 늘 하나만 1입니다. 플립플롭은 N개지만 다음 상태 논리가 아주 단순합니다. 플립플롭이 넉넉한 FPGA에서 합성 도구가 기본으로 고르는 경우가 많습니다.
  • gray: 차례로 넘어가는 상태끼리 한 비트만 다르게 번호를 붙입니다. 5장의 그레이 코드와 같습니다.

번호 붙이는 방식은 출력에도 영향을 줍니다. 상태 비트들은 엣지 뒤 조금씩 다른 시각에 바뀌므로, binary에서 01→10으로 갈 때 아주 잠깐 11이나 00을 거칠 수 있습니다. 상태를 해석해서 바로 내보내는 조합 출력에는 이 순간이 글리치로 튀어나옵니다.

출력을 레지스터로 내면(다음 상태를 보고 미리 계산해서 엣지에 맞춰 내보내면) 글리치가 사라지고, 다음 회로가 받는 타이밍도 깔끔해집니다. 다른 클럭 도메인이나 칩 바깥으로 나가는 출력, 리셋이나 enable처럼 글리치가 치명적인 신호는 꼭 레지스터로 내보냅니다.

3.6맞게 만들었는지 확인하기: 테스트벤치

회로를 만들었으면 맞는지 확인해야 합니다. 시뮬레이션용 Verilog 모듈인 테스트벤치가 설계한 회로(DUT)에 입력을 넣고, 같은 입력을 넣은 정답 모델의 결과와 비교합니다. 사람이 파형을 눈으로 보는 대신 테스트벤치가 스스로 맞고 틀림을 판단하게 만드는 것이 핵심입니다(self-checking).

module tb;
  reg clk = 0, rst = 1, start = 0;
  reg  [7:0] a_in, b_in;
  wire [7:0] A;  wire done;
  gcd dut (.clk(clk), .rst(rst), .start(start), .a_in(a_in), .b_in(b_in), .A(A), .done(done));

  always #5 clk = ~clk;                        // 클럭 만들기 (합성 안 됨)

  function [7:0] gold (input [7:0] x, input [7:0] y);   // 정답 모델
    begin
      while (x != y) if (x > y) x = x - y; else y = y - x;
      gold = x;
    end
  endfunction

  integer i, err = 0;
  initial begin
    #20 rst = 0;
    for (i = 0; i < 100; i = i + 1) begin
      a_in = 1 + {$random} % 255;  b_in = 1 + {$random} % 255;
      @(negedge clk) start = 1;               // 입력은 반대쪽 엣지에서 바꾼다
      @(negedge clk) start = 0;
      wait (done);  @(negedge clk);
      if (A !== gold(a_in, b_in)) begin
        err = err + 1;
        $display("틀림: gcd(%0d, %0d) = %0d", a_in, b_in, A);
      end
    end
    $display("검사 100개 중 오류 %0d개", err);
    $finish;
  end
endmodule
  • 입력을 클럭의 반대쪽 엣지(negedge)에서 바꾸면, 회로가 입력을 읽는 상승 엣지와 겹치지 않아 1장에서 본 것 같은 순서 문제가 생기지 않습니다.
  • 무작위 입력 100개로 끝내지 말고, 경계 사례(a=b, a=1, 255와 1 등)도 따로 넣습니다.
  • 테스트가 통과하지 않으면 파형을 봅니다. 아래에서 연습해 봅시다.
이 장의 요점
  • 숫자는 데이터패스가, 순서는 컨트롤러가 맡고, 둘은 상태 신호와 제어 신호로 대화합니다.
  • 알고리즘 → 재료 정하기 → ASMD 차트 → 데이터패스 → 컨트롤러 표 순서로 설계합니다.
  • always @(*)에는 기본값을 먼저 쓰고, 바깥으로 나가는 출력은 레지스터로 냅니다.
  • 테스트벤치는 정답 모델과 스스로 비교하게 만듭니다.
