RTL로 생각하기

클럭 엣지마다 레지스터가 한꺼번에 바뀐다는 감각을 익히고, = 와 <= 의 차이를 회로로 확인합니다.

1.1코드는 순서대로, 회로는 동시에

C에서 a = b; b = a;는 위에서 아래로 한 줄씩 실행됩니다. 하드웨어에는 실행 순서라는 것이 없습니다. 모든 게이트는 늘 동시에 동작하고, 무언가를 기억하는 부품은 플립플롭(레지스터)뿐입니다.

그래서 하드웨어 설계자는 이렇게 묻습니다. “다음 클럭 엣지에서 각 레지스터에 어떤 값이 들어가야 하는가?” 이 질문에 답하는 방식으로 회로를 적는 것이 RTL(Register Transfer Level) 설계입니다. 지난 학기에 만든 Mealy/Moore 머신도 사실 RTL입니다. 상태 레지스터 하나와, 다음 상태를 계산하는 조합 논리로 이루어져 있으니까요.

1.2레지스터와 조합 논리

동기 회로는 두 종류의 부품으로 나뉩니다.

  • 레지스터는 클럭 상승 엣지 순간의 입력 D를 잡아서, 다음 엣지까지 출력 Q로 내보냅니다.
  • 조합 논리는 기억이 없습니다. 입력이 바뀌면 약간의 지연 뒤 출력이 따라 바뀝니다.

한 클럭 주기 동안 조합 논리는 현재 Q 값들로 다음 D 값을 계산해 둡니다. 엣지가 오면 모든 레지스터가 동시에 D를 Q로 옮깁니다. 아래 회로는 입력이 세 클럭 연속 1이면 out이 1이 되는 검출기입니다. 입력을 바꾸고 클럭을 눌러 보세요.

파형에서 out을 보세요. 클럭 엣지에 맞춰 바뀌는 것처럼 보이지만, 그건 입력인 r1~r3가 엣지에서 바뀌기 때문입니다. AND 게이트 자체는 클럭을 모릅니다.

1.3<=와 =

Verilog에는 대입이 두 가지 있습니다. 논블로킹 대입 <=는 “엣지 순간의 옛 값들로 우변을 모두 계산한 뒤, 블록이 끝날 때 한꺼번에 바꾼다”는 뜻입니다. 블로킹 대입 =는 “지금 바로 바꾸고, 다음 줄은 바뀐 값을 본다”는 뜻입니다. 앞의 것은 레지스터들이 동시에 갱신되는 하드웨어와 정확히 같고, 뒤의 것은 C와 비슷합니다.

두 가지 규칙 always @(posedge clk) 안, 즉 순차 논리에서는 <=를 씁니다.
always @(*) 안, 즉 조합 논리에서는 =를 씁니다.
한 always 블록 안에서 둘을 섞지 않습니다.

1.4reg로 선언했다고 레지스터가 되지는 않는다

Verilog의 reg는 “always 블록 안에서 대입되는 변수”라는 문법상 표시일 뿐입니다. 플립플롭이 생기는지는 클럭 엣지에서 대입되는가로 결정됩니다.

reg y;
always @(*) begin          // 클럭이 없음
  if (sel) y = a;
  else     y = b;           // y는 그냥 2:1 MUX의 출력 (조합 논리)
end

반대로 always @(*) 안에서 어떤 경우에 값을 대입하지 않으면, 이전 값을 기억해야 하므로 합성기가 원치 않는 래치(latch)를 만듭니다. 이 문제는 3장에서 다시 봅니다.

1.5if와 case는 어떤 회로가 되나

조합 논리를 always @(*)로 쓸 때, 같은 동작이라도 쓰는 방식에 따라 회로 모양이 달라집니다. if-else if 사슬은 “앞의 조건이 먼저”라는 뜻이라 2:1 MUX가 줄줄이 이어진 우선순위 회로가 되고, case는 선택 신호 하나로 고르는 병렬 MUX가 됩니다. 사슬 끝에 있는 입력은 MUX를 여러 단 거쳐야 하므로, 2장에서 볼 크리티컬 패스가 길어집니다.

우선순위가 꼭 필요할 때(예: 인터럽트 중 가장 급한 것 고르기)는 if-else가 맞습니다. 그렇지 않다면 case로 쓰는 편이 회로가 얕고 의도도 분명합니다. 마지막 경우처럼 어떤 조건에서 값을 정하지 않으면, 회로가 이전 값을 기억해야 하므로 래치가 생깁니다.

1.6시뮬레이션은 맞는데 회로는 다를 때

Verilog 시뮬레이터는 코드를 글자 그대로 실행하고, 합성기는 코드의 뜻을 회로로 바꿉니다. 둘이 다르게 해석하는 코드를 쓰면, 시뮬레이션에서 확인한 동작과 실제 칩의 동작이 달라집니다. 가장 흔한 예가 감지 목록을 빠뜨린 경우입니다.

always @(a)          // b가 빠졌다
  y = a & b;

시뮬레이터는 a가 바뀔 때만 이 블록을 실행하므로, b만 바뀌면 y가 그대로입니다. 합성기는 감지 목록을 보지 않고 그냥 AND 게이트를 만듭니다. 아래 파형의 b 칸을 눌러 바꿔 보세요.

그 밖에 자주 만나는 불일치는 이렇습니다.

  • #5 같은 지연은 시뮬레이션에서만 의미가 있고, 합성기는 무시합니다.
  • initial 블록의 초기값은 ASIC에서는 무시되고, FPGA에서는 전원이 켜질 때의 값으로만 쓰입니다. 동작 중에 다시 처음 상태로 돌리려면 리셋을 써야 합니다.
  • always @(*)를 쓰면 감지 목록을 도구가 알아서 채우므로 위 문제가 사라집니다. 조합 논리에는 항상 이것을 쓰세요.

1.7모듈을 여러 벌 찍어 내기: 계층, parameter, generate

큰 회로는 작은 모듈을 여러 번 불러(인스턴스) 조립합니다. 모듈 인스턴스 하나는 그 회로 한 벌이 실제로 칩에 하나 더 생긴다는 뜻입니다. 11장의 PE 64개짜리 배열을 손으로 64번 적을 수는 없으니, 크기를 바꿀 수 있게 쓰는 두 가지 도구가 필요합니다.

  • parameter: 비트 폭이나 개수를 모듈 밖에서 정할 수 있게 하는 상수입니다. shreg #(.N(8), .W(16)) u0 (...)처럼 부를 때 바꿉니다.
  • for와 generate: 하드웨어를 반복해서 적는 문법입니다. 실행 중에 도는 반복이 아니라 합성할 때 펼쳐져서 회로가 N벌 생깁니다. 7장 HLS의 UNROLL과 같은 생각입니다.
module shreg #(parameter N = 4, parameter W = 8) (
  input clk, input [W-1:0] d, output [W-1:0] q);
  reg [W-1:0] r [0:N-1];
  integer i;
  always @(posedge clk) begin
    r[0] <= d;
    for (i = 1; i < N; i = i + 1)   // 합성 때 N-1줄로 펼쳐짐
      r[i] <= r[i-1];
  end
  assign q = r[N-1];
endmodule

// 모듈을 N벌 이어 붙이기 (11장 PE 한 줄과 같은 모양)
genvar k;
generate
  for (k = 0; k < 4; k = k + 1) begin : g_pe
    pe #(.W(8)) u_pe (.clk(clk), .a_in(a_link[k]), .a_out(a_link[k+1]),
                      .p_in(p_in[k]), .p_out(p_out[k]));
  end
endgenerate
이 장의 요점
  • 하드웨어는 모두 동시에 동작하고, 상태는 레지스터에만 있습니다. RTL은 “다음 엣지에 각 레지스터에 무엇이 들어갈지”를 적는 것입니다.
  • 순차 논리는 <=, 조합 논리는 always @(*)와 =.
  • if-else 사슬은 우선순위 MUX, case는 병렬 MUX가 됩니다. 값을 정하지 않는 경로가 있으면 래치가 생깁니다.
  • parameter와 generate의 for는 합성할 때 회로를 여러 벌 펼쳐 적는 문법입니다.
  • 감지 목록, #지연, initial처럼 시뮬레이션과 합성이 다르게 읽는 코드를 피합니다.

책에서 이어 읽기 책은 RTL을 직접 가르치지 않지만, 1.2 FPGA Architecture와 1.3 FPGA Design Process를 읽을 때 이 장의 레지스터·조합 논리 구분이 바탕이 됩니다.
