11장

시스톨릭 배열

FIR의 곱셈기 사슬을 격자로 펼쳐 행렬 곱을 하는 배열을 만들고, 타일링과 배치가 속도를 어떻게 정하는지 봅니다.

11.110장의 FIR에서 출발하기

10장의 전치형 FIR을 다시 보세요. 곱셈기 네 개가 나란히 있고, 곱한 값은 레지스터를 지나며 옆으로 더해졌습니다. 이렇게 같은 모양의 작은 처리 단위(PE)를 줄지어 놓고, 데이터를 매 사이클 이웃에게만 넘기는 구조를 시스톨릭(systolic) 배열이라고 합니다. 심장이 박동할 때마다 피가 한 칸씩 밀려가는 모습에서 따온 이름입니다.

10장 FIR에는 한 가지 약점이 있었습니다. x가 긴 선 하나로 네 곱셈기에 동시에 뿌려졌습니다(브로드캐스트). PE가 4개일 때는 괜찮지만 수백 개로 늘어나면 이 선이 길어져서 2장의 크리티컬 패스가 됩니다. 그래서 진짜 시스톨릭 배열은 입력도 레지스터를 거쳐 한 칸씩 넘깁니다. 모든 선이 이웃 PE까지만 가므로, 배열을 아무리 키워도 클럭이 느려지지 않습니다.

11.2PE 하나

구글 TPU가 쓰는 가중치 고정(weight-stationary) 방식의 PE는 가중치 w 하나를 미리 실어 두고, 매 사이클 다음 일을 합니다.

  • 왼쪽에서 입력 a를 받아 그대로 오른쪽 PE로 넘깁니다.
  • 위에서 부분합 p를 받아 p + a·w를 아래 PE로 넘깁니다.
module pe (input clk, input load_w,
           input  signed [7:0]  a_in, w_in,
           input  signed [31:0] p_in,
           output reg signed [7:0]  a_out,
           output reg signed [31:0] p_out);
  reg signed [7:0] w;
  always @(posedge clk) begin
    if (load_w) w <= w_in;      // 가중치는 한 번 싣고 그대로
    a_out <= a_in;              // 입력은 오른쪽으로
    p_out <= p_in + a_in * w;   // 부분합은 아래로
  end
endmodule

1장의 시프트 레지스터와 4장의 파이프라인 레지스터, 곱셈기 하나와 덧셈기 하나가 전부입니다. 이 PE를 K×N 격자로 깔면, 위에서 아래로 내려가는 한 열이 내적 하나를 계산합니다. 열 n의 맨 아래로 나오는 값은 Σk x[k]·W[k][n], 즉 벡터와 행렬의 곱의 n번째 원소입니다.

11.3왜 입력을 비스듬히 넣어야 하나

행 k의 PE에 도착한 부분합은 위쪽 PE들을 거치느라 k 사이클 늦게 도착합니다. 그러니 행 k에 들어가는 입력도 k 사이클 늦게 넣어야 같은 벡터끼리 만납니다. 그래서 입력 행렬을 계단 모양으로 비스듬히(skew) 밀어 넣고, 계산은 대각선 물결처럼 배열을 훑고 지나갑니다.

“한꺼번에”로 바꿔서 돌려 보세요. 계산은 똑같이 일어나지만, 아래쪽 행에서 서로 다른 벡터의 부분합과 입력이 만나 엉뚱한 값이 나옵니다. 4장에서 c1 <= c로 박자를 맞추지 않았을 때와 똑같은 버그입니다.

벡터 하나가 들어가서 마지막 결과가 나오기까지 K + N − 1 사이클이 걸리지만, 배열이 꽉 차면 매 사이클 새 벡터가 들어가고 매 사이클 결과가 나옵니다. 4×4 배열은 사이클마다 곱셈 16개를 합니다.

11.4배열보다 큰 행렬: 타일링

실제 행렬은 배열보다 훨씬 큽니다. 64×16 가중치를 8×8 배열에서 곱하려면 가중치를 8×8 조각(타일) 8×2 = 16개로 나누고, 타일을 하나씩 실어 가며 돌린 뒤 같은 출력에 해당하는 부분합을 누산기에 더합니다. 이때 시간이 어디로 새는지 보겠습니다.

  • 가중치 싣기: 타일마다 S 사이클(한 행씩 밀어 넣음).
  • 채우기와 비우기: 첫 입력이 배열을 가로지르고 마지막 결과가 빠져나오는 데 약 2S 사이클. 이 동안 배열의 일부만 일합니다.
  • 흘리기: 입력 벡터 M개(배치)가 지나가는 M 사이클. 배열이 꽉 차서 일하는 구간입니다.
배치가 중요한 이유 배치가 작으면 배열은 가중치를 싣고 채우고 비우는 데 대부분의 시간을 씁니다. TPU 같은 가속기가 여러 입력을 모아서(배치) 한꺼번에 처리하려는 이유이고, “다음 가중치 미리 싣기”처럼 가중치 레지스터를 두 벌 두는 이유이기도 합니다. 7장에서 메모리 포트가 II를 막았던 것처럼, 여기서는 가중치를 가져오는 속도가 배열을 굶길 수 있습니다.

11.5진짜 이유: 데이터 재사용

11.1에서는 선이 짧아진다는 점을 강조했지만, 시스톨릭 배열이 빠른 더 근본적인 이유는 한 번 읽은 값을 여러 PE가 돌려 쓴다는 데 있습니다. MAC 하나로 행렬 곱을 하면 곱셈 한 번마다 메모리에서 값 두 개를 읽어야 합니다. 메모리는 사이클당 몇 개밖에 못 내주므로(8장), MAC을 아무리 늘려도 메모리가 따라오지 못합니다.

S×S 배열은 사이클마다 입력 S개를 왼쪽에서 받고 결과 S개를 아래로 내보내면서 곱셈을 S²번 합니다. 가중치는 타일마다 한 번 싣고 배치 M개 동안 계속 씁니다. 그래서 곱셈 한 번에 필요한 메모리 접근이 배열이 커질수록, 배치가 클수록 줄어듭니다.

11.7행렬 곱이 아닌 시스톨릭: 삽입 정렬

시스톨릭 배열은 행렬 곱 전용이 아닙니다. 같은 모양의 셀을 한 줄로 늘어놓고 스트림으로 이으면 정렬도 됩니다. 각 셀은 값 하나를 들고 있다가, 들어온 값이 더 작으면 그것을 들고 원래 값을 오른쪽으로 넘기고, 아니면 들어온 값을 그대로 넘깁니다. 모든 값이 지나가고 나면 셀들이 왼쪽부터 작은 순서로 값을 들고 있습니다.

void cell(hls::stream<int> &in, hls::stream<int> &out) {
  int keep = INT_MAX;                     // 아직 빈 칸
  for (int i = 0; i < N; i++) {
#pragma HLS PIPELINE II=1
    int v = in.read();
    if (v < keep) { out.write(keep); keep = v; }
    else          out.write(v);
  }
}
// 맨 위 함수에서 #pragma HLS DATAFLOW 아래에 cell을 N개 줄줄이 부른다

9장의 DATAFLOW와 스트림으로 셀들을 잇는 코드입니다. 셀 N개가 동시에 일하므로 N개 정렬이 약 2N사이클에 끝납니다. CPU의 삽입 정렬은 N²에 비례합니다.

11.8블록 행렬 곱을 HLS 코드로

11.4에서 타일링의 시간표를 봤습니다. 책 7.3절은 같은 생각을 HLS 코드로 씁니다. 행렬 C를 B×B 블록으로 나누고, 블록 하나를 만들 때 A의 B행 묶음과 B행렬의 B열 묶음을 스트림으로 한 줄씩 흘려 받습니다. 한 줄을 받을 때마다 B×B개의 곱을 동시에 더하므로, 이 모양을 바깥 곱(outer product) 방식이라고 합니다. 누산기가 PE에 머무는 11.6의 출력 고정 방식입니다.

void mm_block(hls::stream<vec_t> &a_cols, hls::stream<vec_t> &b_rows, int c[B][B]) {
#pragma HLS ARRAY_PARTITION variable=c complete
  for (int k = 0; k < K; k++) {              // K 방향으로 한 줄씩
#pragma HLS PIPELINE II=1
    vec_t a = a_cols.read();                 // A 블록의 k번째 열 (B개)
    vec_t b = b_rows.read();                 // B 블록의 k번째 행 (B개)
    for (int i = 0; i < B; i++)
      for (int j = 0; j < B; j++)
        c[i][j] += a.v[i] * b.v[j];          // 펼쳐져서 곱셈 B×B개가 동시에
  }
}

한 사이클에 메모리(스트림)에서 2B개를 받고 곱셈을 B²번 합니다. 11.5의 데이터 재사용과 같은 계산입니다. 블록 크기 B는 칩 안 메모리와 DSP 개수로 정하고, 블록 하나가 끝나면 다음 블록의 스트림을 흘립니다. 이 블록 함수 앞뒤에 A와 B를 블록 순서로 읽어 오는 함수와 C를 내보내는 함수를 두고 DATAFLOW로 이으면 9장의 구조가 됩니다.

11.9병합 정렬을 하드웨어 모양으로

CPU에서 병합 정렬은 보통 재귀로 씁니다. 재귀 호출은 합성할 수 없으므로, 하드웨어에서는 길이 1, 2, 4, …짜리 묶음을 차례로 합치는 반복문으로 바꿉니다(책 10.3).

for (int width = 1; width < N; width *= 2)          // log2 N 단계
  for (int i = 0; i < N; i += 2 * width)
    merge(in, out, i, i + width, i + 2 * width);     // 정렬된 두 묶음을 합친다
// 단계마다 in과 out을 바꿔 쓴다

단계 수가 log2N으로 정해져 있으므로 단계마다 함수 하나와 버퍼 하나를 두고 DATAFLOW로 이으면, 여러 묶음의 정렬이 단계별로 겹쳐 흘러갑니다. 11.7의 삽입 정렬 배열은 셀이 N개 필요하지만, 이 방식은 단계 log2N개면 되는 대신 각 단계가 원소 하나씩 순서대로 처리합니다. 같은 문제도 재구성 방식에 따라 자원과 처리율의 균형이 달라집니다.

실제 도구에서는실제 TPU는 128×128 이상의 배열과 큰 누산기 메모리, 가중치를 미리 싣는 이중 버퍼를 씁니다. HLS 도구가 평범한 C 코드에서 시스톨릭 배열을 자동으로 만들어 주지는 않으므로, PE를 함수로 쓰고 스트림과 DATAFLOW로 잇는 식으로 구조를 직접 적습니다.
이 장의 요점
  • 시스톨릭 배열은 이웃끼리만 데이터를 넘기는 같은 모양 PE의 격자입니다.
  • 입력을 비스듬히 넣어야 같은 벡터끼리 만납니다.
  • 진짜 이득은 데이터 재사용입니다. 배치가 작으면 싣기와 채우기 비용이 큽니다.
  • 정렬처럼 행렬 곱이 아닌 문제도 시스톨릭으로 풀 수 있습니다.
