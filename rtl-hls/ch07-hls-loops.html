7장

HLS 루프 지시어

PIPELINE, UNROLL, ARRAY_PARTITION을 바꿔 가며 II와 latency가 어떻게 변하는지 봅니다.

7.1루프가 시간을 먹는다

6장 끝에서 본 것처럼, 지시어 없이 합성한 루프는 반복 하나를 완전히 끝낸 뒤에야 다음 반복을 시작합니다. 반복 한 번이 10사이클이고 64번 돌면 640사이클입니다. HLS 코드를 빠르게 만드는 일은 대부분 루프를 다루는 일이고, 이때 쓰는 도구가 지시어(pragma)입니다. 코드의 의미는 그대로 두고, 하드웨어를 어떻게 만들지만 도구에 알려 줍니다.

  • PIPELINE: 4장의 파이프라이닝을 루프에 적용합니다. 반복 하나가 끝나기를 기다리지 않고 II 사이클마다 새 반복을 시작합니다.
  • UNROLL: 루프 몸체를 여러 벌 복사해서, 한 번에 여러 반복을 처리합니다. 연산기도 그만큼 늘어납니다.
  • ARRAY_PARTITION: 배열을 여러 메모리로 쪼개서 한 사이클에 읽을 수 있는 원소 수를 늘립니다.

파이프라인 루프를 볼 때 쓰는 말 세 가지를 기억하세요.

  • IL(iteration latency): 반복 하나가 처음부터 끝까지 걸리는 사이클.
  • II(initiation interval): 다음 반복을 시작하기까지의 간격. II=1이면 매 사이클 새 반복이 시작됩니다.
  • 전체 사이클 ≈ (반복 횟수 − 1) × II + IL

II를 목표만큼 못 줄이게 막는 원인은 크게 둘입니다. 자원(메모리 포트가 모자람)과 의존성(이번 반복이 이전 반복의 결과를 기다려야 함)입니다.

7.2실험에서 찾아볼 것

  1. 벡터 연산에서 PIPELINE II=1만 켜 보세요. 전체 사이클이 거의 IL배 줄어듭니다.
  2. 여기에 UNROLL 4를 더하면 II가 2로 올라갑니다. 매 사이클 a에서 4개를 읽어야 하는데 포트는 2개뿐이기 때문입니다. cyclic 2로 쪼개면 다시 II=1이 됩니다.
  3. 내적에서는 PIPELINE II=1을 줘도 II가 4입니다. sum에 더하려면 이전 반복의 덧셈(4사이클)이 끝나야 하기 때문입니다. UNROLL을 해도 덧셈이 줄줄이 이어질 뿐 나아지지 않습니다.
  4. 부분합 4개로 바꾸면 연속된 반복이 서로 다른 p[]에 더하므로 의존성이 끊기고 II=1이 됩니다. 코드를 조금 바꾸는 것이 지시어보다 효과가 큰 경우입니다.
세 지시어는 함께 쓴다 UNROLL만 하면 메모리 포트가 막히고, ARRAY_PARTITION만 하면 늘어난 포트를 쓸 연산이 없습니다. PIPELINE만 하면 의존성에 걸릴 수 있습니다. 실제 HLS 리포트에서 II가 목표보다 크게 나오면, 리포트가 알려주는 원인(자원인지 의존성인지)부터 확인하세요.

7.3II는 어떻게 정해지나: 공식으로 정리

실험 7-1의 리포트 문구를 공식으로 바꾸면 이렇습니다. 책 1.4.3절의 핵심이고, 앞으로 모든 장에서 II를 따질 때 이 식을 씁니다.

II = max( II자원, II재귀, 목표 II )
  • II자원 = 자원마다 ⌈반복 한 번에 그 자원을 쓰는 횟수 ÷ 그 자원의 개수⌉ 중 가장 큰 값. 메모리라면 “개수”는 포트 수(BRAM 하나에 2)입니다.
  • II재귀 = 되먹임 고리마다 ⌈고리를 한 바퀴 도는 지연 ÷ 의존 거리⌉ 중 가장 큰 값. 의존 거리는 “몇 번째 앞 반복의 결과를 쓰는가”입니다. sum += a[i]는 바로 앞 반복이라 거리 1, p[i%4] += …는 네 번째 앞 반복이라 거리 4입니다.

연습: 공식으로 직접 계산해 보세요.

  1. 반복마다 배열 a에서 6개를 읽고, a를 cyclic 2로 나눴습니다. 다른 제약이 없다면 II는?
  2. y[i] = y[i-1] * c + x[i]에서 곱셈 3사이클, 덧셈 1사이클입니다. II는?
  3. 2번을 y[i] = y[i-3] * c + x[i]로 바꾸면 II는?
답 보기
  1. 포트 수 = 뱅크 2 × 포트 2 = 4. ⌈6 ÷ 4⌉ = 2.
  2. 고리 = 곱셈 3 + 덧셈 1 = 4사이클, 거리 1. ⌈4 ÷ 1⌉ = 4.
  3. 거리가 3이 되어 ⌈4 ÷ 3⌉ = 2. 의존 거리를 늘리는 것이 4장 부분합 기법의 원리입니다.

7.4지시어보다 먼저: 코드 재구성

지시어는 코드가 허락하는 범위 안에서만 효과를 냅니다. 같은 일을 하는 코드라도 모양을 조금 바꾸면 도구가 만들 수 있는 회로가 크게 달라집니다. 10장의 FIR 필터를 HLS로 처음 쓰면 흔히 이런 모양이 됩니다.

  • 조건문 빼내기(code hoisting): 특정 반복에서만 참이 되는 조건은 루프 밖으로 꺼냅니다. 루프 몸체가 매 반복 똑같아지면 파이프라인과 펼치기가 쉬워집니다.
  • 루프 쪼개기(loop fission): 성격이 다른 두 일을 한 루프에 섞지 말고 루프 둘로 나눕니다. 그러면 각 루프에 맞는 지시어를 따로 줄 수 있습니다. 여기서는 시프트를 완전히 펼쳐 시프트 레지스터로 만들고, 곱셈-누산은 파이프라인합니다.

7.5중첩 루프는 어디를 파이프라인하나

실제 코드는 대부분 루프 안에 루프가 있습니다. 행렬-벡터 곱으로 보겠습니다.

ROW: for (int i = 0; i < 8; i++) {
  int acc = 0;
  COL: for (int j = 0; j < 8; j++)
    acc += M[i][j] * x[j];
  y[i] = acc;
}

PIPELINE을 안쪽 루프에 주면 안쪽만 파이프라인되고, 바깥 반복이 바뀔 때마다 파이프라인이 비었다 다시 찹니다. 바깥 루프에 주면 그 안의 루프는 모두 펼쳐집니다. 안쪽 루프가 완전한 직사각형 모양(바깥과 안쪽 사이에 다른 코드가 없음)이면 두 루프를 하나로 합치는(flatten) 방법도 있습니다.

7.6반복 횟수를 모를 때

루프 경계가 실행할 때 정해지는 변수라면, 도구는 반복 횟수를 알 수 없어 리포트의 latency 칸에 “?”를 씁니다. 희소 행렬처럼 행마다 원소 수가 다른 경우가 대표적입니다.

for (int i = 0; i < n; i++) {          // n은 실행 중에 정해짐
#pragma HLS LOOP_TRIPCOUNT min=1 max=64 avg=16
#pragma HLS PIPELINE II=1
  sum += val[i] * x[col[i]];
}

LOOP_TRIPCOUNT는 리포트에 쓸 예상 반복 횟수를 알려 줄 뿐 회로는 바꾸지 않습니다. 경계가 변수인 루프는 완전히 펼칠 수도 없습니다. 펼치고 싶다면 최대 횟수로 루프를 쓰고 안에서 if (i < n)로 막는 식으로 고칩니다. 이때도 6.4에서 본 것처럼 그 조건문은 하드웨어로 남습니다.

실제 도구에서는최신 Vitis HLS는 지시어가 없어도 안쪽 루프를 자동으로 파이프라인하는 경우가 많아서, 이 장의 “PIPELINE 없음”과 기본 결과가 다를 수 있습니다(버전과 설정에 따라 다름). 끄려면 #pragma HLS PIPELINE off를 씁니다. 목표 II를 못 맞추면 리포트에 원인(메모리 포트 부족, 반복 사이 의존성 등)이 경고로 나오므로 그것부터 읽으세요. 루프에 이름표(ROW: for)를 붙이면 리포트에서 찾기 쉽습니다.
이 장의 요점
  • 전체 사이클 ≈ (반복 횟수 − 1) × II + IL.
  • PIPELINE은 겹치기, UNROLL은 복사입니다. 둘 다 메모리 포트와 반복 사이 의존성에 막힙니다.
  • 지시어보다 코드 재구성(조건문 빼내기, 루프 쪼개기)이 먼저입니다.
  • 중첩 루프는 어디를 파이프라인하느냐가 결정적입니다. 바깥을 하면 안쪽이 모두 펼쳐집니다.
